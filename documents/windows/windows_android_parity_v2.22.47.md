# 十倍率 Windows 功能对齐与验收记录

Windows 目标版本为 `2.22.47-android-parity`，原正式版为 `2.22.46-ui-refinement`。Android 原型版本为 `2.22.45-local-startup`。本轮以 Android 现有入口、状态规则和共享 Rust 业务代码为对照，扩展 Windows 客户端。测试使用隔离目录和合成数据。

发布状态：正式版已发布。发布清单、源码快照、可执行文件完整性链及独立验证均通过，`tools/windows.ps1 verify` 返回 0。固定启动入口已打开新版本，实机窗口显示 v2.22.47，原有账户保持登录，1 个运行中的计时已保留。

新增 9 项业务状态测试通过，覆盖当日统计边界、最近记录上限、拖动排序及跨账户拦截、闰日与期间边界、财务数据不足、风险操作目的地、历史版本分享、诊断会话持久化和敏感内容排除、加密富文本转文本的恢复数据，以及六页财务浏览不修改账目。测试计数以最终发布套件为准，不将定向重跑重复累加。

变异检查的两种结果均符合预期。将“今日计时”改为“今日记录”后，业务测试通过；移除跨账户判断后，拖动边界测试在断言处失败。检查结束后源码已按原始字节恢复，恢复前后 SHA-256 相同。记录见 `mutation_result.json`、`mutation_cosmetic.log`、`mutation_guard.log`。

原生后台测试通过实际窗口关闭处理进入通知区，隐藏期间记录到 14 次更新，计时推进 5.060 秒，之后恢复窗口且任务仍在运行。测试总耗时 13.30 秒。最初测试发现 winit 的隐藏窗口收不到绘制事件，已通过窗口所属线程的原生消息队列定时唤醒修复，隐藏期间不再绘制完整界面。

原生界面覆盖 27 种窗口场景，包括浅色、深色、OLED、空态、运行态、详情及 760×480 的最小窗口。财务六页另用完整合成账目复核。所有截图均为完整应用窗口的内容区。最后一次原生界面测试通过，并生成可实际解码的 1080 像素宽 PNG 长图。检查修正了拖动柄缺字、详情重复信息、预算金额重复和健康分项显示尺度。富文本目录脚本通过 JavaScript 语法检查。完整客户端回归还发现最小窗口中正文被新增工具栏挤出首屏，现已将次要操作收进菜单，原有可见性及返回搜索测试通过，原生最小窗口也已复核。

## 使用变化

在计时卡左上角拖动六点标记即可调整顺序，点击“详情”查看单格统计。在便签上方可以复制内容或导出文字、长图、HTML；小窗口通过“文档操作”打开这些入口。在“财务”的“风险分析”中选择期间和概览页面，在“我的”中调整语言、通知区行为和诊断收集。

默认关闭窗口后继续在通知区运行。需要结束程序时，在通知区图标菜单中选择“退出”；也可以在“我的”中取消关闭后继续运行。

## 验证范围

本轮验证围绕 Windows 本地状态、原生窗口及正式构建展开。没有运行 Android 模拟器，也没有对手机执行运行测试。真实账号与手机的双向同步、外部 AI 服务调用、多显示器与不同缩放组合、系统休眠唤醒及长时间持续运行不计为本次已验证场景。短时后台测试证明当前关闭与恢复路径能够继续推进计时，不代表所有系统场景都已覆盖。

证据目录：`release_artifacts/verification/v2.22.47-android-parity/`。初次失败与修正后的日志均保留，最终结论以 `runtime_final.log`、`runtime_status.json`、`visual_release.log`、`visual_review_result.json` 、`package_final.log`、`verify_final.log`、`published_artifact_checks.json`、`formal_self_check/self_check_result.json`、`stable_entry_result.json` 和 `production_launch_result.json` 为准。
