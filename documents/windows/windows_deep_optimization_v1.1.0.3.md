# Windows 1.1.0.3 性能与发布验证

记录日期：2026-10-02。实际正式版本以 `release_artifacts/current/release_manifest.json` 为准。本文中的局部性能结果不能代表完整客户端启动、整机响应或所有工作区的表现。

## 本次实现

### 固定桌面入口与版本交接

桌面使用固定的 `TenRate.lnk`，目标是 `release_artifacts/desktop_entry` 内的稳定启动器。启动器读取正式发布清单，核对客户端大小、SHA-256 及发布身份，解析当前版本后启动。发布流程在原子提交正式清单之后维护桌面入口，修正目标、工作目录和图标；只处理目标路径确实属于当前项目的旧快捷方式，未知项目保留。

本版引入版本化的本机交接协议。同版或更旧的请求激活已有窗口；更高版本请求先由旧窗口保存编辑草稿、等待已受理的计时操作及持久化完成，再释放资料锁。保存失败保留原窗口及草稿。交接开始前核对请求进程存活与有效期限，尚未开始的请求可取消；保存退出流程开始后继续安全完成已受理的写盘。启动方最多等待45秒，超时显示处理提示。启动和恢复阶段使用已有后台任务取消及等待机制。较早、不支持该协议的版本仍需要正常退出后重新点击入口。

图标使用深青色背景、金色数字10与向上箭头，表达记录、专注和积累。原生 SVG 源及16至256像素 ICO 保留在 `native/gridtimer_native/assets/windows`。稳定启动器和客户端内嵌同一图标，窗口、任务栏和托盘使用对应资源。Win32 `ExtractIconEx` 已实际读出大小图标，不能仅以文件存在认定资源正确。

### 工作区启动与持久化

已有当前格式的 SQLite 工作区直接执行完整 `integrity_check`，减少此前 quick 与 full 两次首次检查；历史审计后的 `quick_check`、结构、外键、所属账户和独立恢复证据检查继续执行。

同一个 Immediate 启动事务中，未发生写入时复用已经审计过的所属账户最新快照。隔离、隐私修复和 SQL 触发器导致写入后，重新读取并完整核验返回记录。普通保存的隐私规范化结果只在当前操作内复用，不增加跨操作明文缓存。没有采用 SQLite mmap 调整。

### 知识读取缓存

快速导航按笔记内容版本、查询和访问路径缓存父目录索引与结果，最多80条结果及两个命令。加密和已删除页面不显示原始标题，内容、工作区和隐私状态变化使缓存失效。

数据库列表复用与记录 Arc 快照严格绑定的编号索引。搜索结果同时绑定来源行 Arc、当前记录 Arc、笔记版本和规范化查询；只有一个当前索引及一个搜索缓存，不随查询次数无限增长。外来或临时快照不能复用或覆盖当前工作区索引，原记录次序保留。

### 计时读取和响应

计时投影、历史和每日统计按计时内容版本失效。笔记变化可以保留界面已有读模型，减少界面线程重复解析；后台持久化工作仍按原规则核验资料。计时、记录次序、类别、未来元数据以及不能分类的直接修改继续使读模型失效。

本版同时保留既有候选中的计时响应改动：点击时显示处理中，最多保留一次等待请求，使用点击时刻确定开始或暂停时间，持久化成功后才确认新状态；保存失败、工作区或运行身份变化时撤销过期请求。旧计时性能测量保留在 `windows_timer_latency_v1.1.0.3.md`，其中不同候选结果不能当作本次最终可执行文件的测量结果。

## 已执行的性能测量

### 工作区启动 API

以下只测 `open_existing_startup_workspace`。独立恢复回调为 `Ok(())`，使用未登录的合成所属账户，排除字体、窗口、绘制和完整客户端启动。夹具建立及记录已预热应用分析和操作系统文件缓存，12次是重复 API 打开，不能作为冷启动测量。每组12次，采用 nearest-rank P50/P95。前后分开顺序执行，没有采样整个过程的 CPU 或内存峰值。

两组数据库均有四条快照、两个所属账户。前后实际 JSON 内容除自动生成的运行及会话编号外相同，字节数相同；原始哈希不同，不能称为完全相同字节的配对实验。比较对象是修改前后的存储库 API 探针，不是完整正式1.1.0.2与1.1.0.3客户端。

|实际最新资料大小 / SQLite 大小|修改前 P50|修改后 P50|修改前 P95|修改后 P95|
|---|---:|---:|---:|---:|
|4,203,308 B / 12,734,464 B|460.592 ms|125.273 ms|771.672 ms|179.555 ms|
|33,563,436 B / 100,900,864 B|3,284.523 ms|2,523.015 ms|4,136.202 ms|4,400.896 ms|

约4 MiB资料的 P50减少72.80%，P95减少76.73%。约32 MiB资料的 P50减少23.18%，但 P95增加6.40%，本轮没有证明大型资料慢端耗时稳定改善。保留这组波动结果，不用后续较快样本替换它。

完整探针身份、快照差异及全部样本位于 `release_artifacts/verification/windows_v1.1.0.3/deep_optimization/storage/startup_api_summary.json`。基线探针 SHA-256 为 `912c3e56af597b83b3eb6731489053b2308a3db18c61dd51e96c8e1ba8f37574`，候选探针为 `2a6ca58dfb99f6de66803846b6ab8e0cf523b899d3913a14f7e6f35919ecc873`。

缓存命中避免了每次重复建索引、复制字符串和筛选。0.1至0.4 μs 接近计时分辨率，不能换算为完整客户端的加速倍数。完整冷重建有额外开销：257条快速导航 P50增加54.5%，2049条数据库列表 P50增加80.4%。这项冷测包含公共索引重建；只修改查询会复用索引，其实际输入耗时本轮未单独测量。

## 发布与容量记录
