# 文档编辑器换行与键盘避让验收

## 范围与基线

本次针对 `NoteDocumentEditor.kt` 的分块文档编辑画布。PR #5 原始基准为 `main@c8dac75acb0d5f8f8f2a487c5d9df22c16a614ca`；本轮本地整合从 `main@3808ef6fa1e18963c88152eb32dfb43504694bc0` 开始，依次接入 PR #4 的知识列表紧凑头部和 PR #5 的光标可见性修复，保留此前的安卓风控修复和 Windows 1.1.0.7 源码。原工作目录、未提交改动、配置及正式签名材料继续保留。

原实现已经通过外层 `imePadding()` 和加权列表给键盘、底部格式栏预留空间。缺失的是两段衔接：换行拆出的新块可能尚未被 LazyColumn 组合，原焦点请求没有先使其可见；已组合文本块没有把新的文本布局与选区末端转换为需要显示的光标矩形。整块滚入可视区也不能解决高于视口的长段落。

## 实现

新模块 `sourcegen/android_document_caret.rs` 由最终源码写出流程调用，只转换文档编辑器。它同时持有生成的 `DocumentCaretPolicy.kt`、`DocumentCaretVisibility.kt` 和 JVM 测试，生成的 Kotlin 不作为人工编辑源提交。

为编辑列表保存与笔记、工作区绑定的 LazyListState；新目标块未进入可视范围时，先按真实列表前缀和块序号定位，再由该块下一帧的焦点请求接手。已可见的长块不跳到块首。列表前缀包含三个固定条目及可选预览切换条目，使用命名 key；新增前缀时须同步索引规则。

本地审查补齐焦点请求的作用域：FocusRequester 与延期一帧的 LaunchedEffect 同时绑定工作区、笔记和块编号。即使工作区切换后保留相同块编号，旧效果也会取消，避免旧输入行继续申请焦点。caret 状态原有的工作区、笔记和块编号绑定保持一致。

实际焦点、TextFieldValue、最新 TextLayoutResult、软件键盘和列表实测高度驱动可取消的 LaunchedEffect。新布局文本必须与当前文本完全相同，选区偏移按 Compose 的 UTF-16 规则处理。等待帧布局后只把光标矩形及 8 dp 余量带入可视范围，不请求整篇或整个长块。请求器挂在没有内边距的文本装饰容器，使用文本局部坐标。

可视高度来自键盘避让后、扣除格式栏的实际列表，不重复扣除键盘或硬编码键盘高度。极小视口下约束请求矩形不超过视口。没有按列表滚动位置或全局位置反复发起请求，避免用户手动阅读时被拉回。新编辑和失焦会取消旧效果，没有固定延迟任务或定时轮询。

不修改正文、选区、中文输入组合串、换行拆块、撤销/重做、保存、加密、AI、同步、主题或格式栏布局，不升级依赖。不记录用户文本、截图内容和输入法日志。

保留 15 项纯布局策略测试，覆盖新行等待布局、同长度编辑旧布局拒绝、空块、失焦或窗口失焦、UTF-16 偏移、长段落矩形、密度余量、小视口、非法坐标、可选前缀索引、已有可见块不跳动和连续行目标范围。Rust 测试只保留必要生成锚点缺失、重复及二次转换时拒绝生成的失败规格，移除仅镜像 UI 字符串、样式或注册实现的断言。

本地变异验证须在隔离临时源码中完成：修改文案或样式后领域测试继续通过；删除布局文本一致性判断或可见块不跳到块首的判断后，相关测试必须失败。不得用变异源码生成交付 APK。

## 真机验收

使用新建的非敏感测试文档，在屏幕底部连续换行至少 30 次，确认每次新段落获得焦点并保持在格式栏上方，不需手动拖动。再在长于一个视口的单块中持续输入至自动折行、粘贴多行及将光标移到中间，确认只移动到当前编辑行，不跳到整个块首或文档末尾。

分别检查中文拼音候选未提交、提交后换行、表情符号、选区替换、段首退格合并、撤销和重做、标题字号变化。文字、选区和组合态须与原逻辑一致；不得靠清除焦点或重置 TextFieldValue 解决遮挡。

检查键盘开关、候选栏高度变化、横竖屏和大字体。工具栏必须保留，键盘顶部不重复留下大块空白。手动上下滚动阅读且不输入时，不应被自动拉回；继续输入时应恢复光标可见。切到预览、关闭笔记或切换笔记/工作区后，旧编辑行的请求不得抢焦点或回滚新页面。

最后回归头部合并、新建/回收站/文档库、图片块与原有知识问答、风控功能。保存后的内容必须完整，不因新滚动逻辑多出或丢失换行。
