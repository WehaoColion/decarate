# 安卓诊断与导出修复记录

版本为 2.22.31-diagnostics-export，版本代码为 22231。包名继续使用 com.ofairyo.gridtimer，沿用项目正式签名。应用修改位于 Rust 源码生成器，未启动或使用安卓模拟器，也未操作真机。

## 问题与修复

用户反馈为点击诊断与导出后提示导出失败或分享失败。本次修复这一链路；此前“开始计时”时闪退尚缺少实际崩溃报告，不能据此认定该闪退已经修复。

数据库备份原先使用 execSQL 执行 PRAGMA app_state_backup.journal_mode=DELETE。该语句返回模式值，不符合 execSQL 的调用条件。现在使用 rawQuery 读取结果，确认返回 delete 后才开始备份事务。数据库 quick_check、冻结快照的一致性检查和完整 ZIP 校验全部保留。调用条件依据 [Android SQLiteDatabase 官方文档](https://developer.android.com/reference/android/database/sqlite/SQLiteDatabase#execSQL(java.lang.String))。

诊断日志改为直接导出，无须先开始记录，也不会清除上次崩溃信息。报告包含设备与版本信息、数据数量摘要、应用事件、已有崩溃报告、系统退出原因和 logcat。日志导出不再序列化整份应用数据，不依赖数据库备份成功。各项独立采集，读取失败会在相应部分记录原因，不阻断其他证据。

日志文件读取有容量限制，logcat 每项最多 256 KiB，当前进程最多 900 行，最近日志最多 1,200 行。logcat 子进程设置 2 秒等待上限，超时后终止；截断和超时均在报告中标明。导出文件先写入唯一临时文件，再关闭、校验并原子发布；记录导出事件失败不会把已经生成的文件误报为生成失败。

数据备份使用固定缓冲区校验 ZIP 条目，不再为每个完整条目分配同等大小的字节数组。仍逐项验证大小、CRC、附件摘要、必需文件，以及两份当前快照与冻结原文的 UTF-8 字节是否完全相同。真正的数据校验失败仍拒绝发布备份。

界面将文件生成和文件交付分为两个操作。生成后显示文件名，用户可以选择“保存到文件”或“分享文件”。分享面板补全 URI 读取授权，打开面板只显示“已打开分享面板”，不会提前宣称对方已经接收。保存通过系统文件选择器写入所选位置，检查写入字节数后才显示成功。失败保留源文件，允许重试，并显示可复制的错误详情。

导出任务由 Activity 的 ViewModel 持有，文件选择器注册在滚动卡片外，避免滚出页面导致任务取消或结果丢失。正在生成状态不作为已完成状态恢复；完成文件路径可恢复。文件选择器等待状态提供“取消等待”，已取消的无请求回调会被忽略，保存绑定发起选择时的源文件。

## 使用方式

覆盖安装新版后，进入“诊断与导出”，点击“导出日志”。显示文件名后点击“保存到文件”，选择手机中的保存位置并确认；也可以点击“分享文件”交给其他应用。数据备份使用“导出数据”生成 ZIP。

如需收集开始计时的闪退，复现后重新打开应用，直接导出日志即可，不需要先开始记录。若文件选择器异常返回后仍显示等待，点击“取消等待”恢复操作。日志采集受系统权限及日志保留范围影响，报告会标明未取得的项目。
