- v2.22.36：优化安卓计时启停、保存与历史检索，保留原计时算法和恢复保护。

本次范围为安卓端，版本为 2.22.36-android-timer，versionCode 22236。实现写在 Rust 源码生成模块 `native/gridtimer_native/src/sourcegen/android_timer_latency.rs`，由现有构建流程生成安卓界面和存储代码。共享计时引擎、Windows 客户端源码和 Windows 正式程序未修改。

正式构建和 Lint 已完成，Lint 为 0 个错误、14 个警告、8 个提示。92 项源码生成测试、32 项计时结果对照、12 项持久化检查和 7 项 SQLite 检查通过。正式签名、ZIP 对齐、三个架构的原生库及最终代码标记均已核验。根目录、APK 目录、当前发布目录和构建输出目录的四份正式 APK 内容一致，三份旧版发布副本已移入 `old_apks`。

交付文件为 `grid_timer_app_v2.22.36-android-timer.apk`，大小 19,212,083 字节，SHA-256 为 `ae5fd42d1dd8ef67f67ab8a1a185ab2d1e63d88d95c38abbabc052f0198d778e`。

计时保存过去每次都会检查全部历史快照，再读取最多 1000 份完整快照逐份解码，而且保存过程持有工作区写锁。现在在首次保存或存储证据改变时进行完整检查，连续保存复用检查结果。验证和数据库写入共用主连接事务，其他数据库连接不能在二者之间提交修改。数据库连接身份、其他连接提交的 data_version、本连接的 total_changes，以及主备 JSON 文件的身份、大小和纳秒时间共同构成缓存条件。保存失败、备份刷新失败、写入不同工作区或检测到变化时，缓存失效。完整历史恢复、当前快照摘要校验、正式事务提交和主备文件保留逻辑继续执行。

开始、暂停和微休息推进只把分类、格子、排序、计时明细和删除标记送入原有原生引擎，修订标记和清洗也只处理这份计时数据。计算完成后，只将格子和计时明细合回当前完整状态，其他模块保留原对象。该投影不用于持久化、备份或网络同步。保存和同步仍使用完整工作区，累计时长、运行身份、阶段切换、删除标记及会话去重沿用原有算法。

详情页的统计和排序、历史页的搜索索引和过滤移到后台计算。搜索加入 120 毫秒输入合并，过期请求的结果不发布到新筛选或新工作区。计算期间显示进度，避免把暂未计算完成误报为没有记录。详情或历史覆盖首页时，底层计时卡片及拖动占位卡片停止逐秒刷新，实际计时继续按时间戳运行。

验证记录位于 `release_artifacts/verification/v2.22.36-android-timer`。计时引擎对照覆盖 32 组启停、多格暂停、重复操作、时间回拨、跨天及长时段补算，投影路径与原路径的格子和会话结果一致，其他领域保持原值。模拟工作区含 1550 条计时明细及较大便签，原生输入从 1,862,691 字节降至 316,678 字节。该数据是主机合成样本，不代表用户手机实测。

生产持久化函数的 JVM 测试覆盖 12 组情形，包括缓存命中、其他连接变更、本连接变更、未来版本主备文件、写盘失败、恢复镜像失败及账户切换。连续 11 次保存只触发 1 次完整历史检查。SQLite 主机测试另外验证了 7 项连接变化、回滚与事务隔离约定。JVM 测试使用受控数据库和文件故障替身，SQLite 测试使用真实主机数据库，均不代替 Android 真机验收。

连接计数的使用依据为 [SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html#pragma_data_version) 与 [Android SQLiteDatabase 事务接口](https://developer.android.com/reference/android/database/sqlite/SQLiteDatabase)。data_version 只在同一连接上比较，因此验证缓存的读取固定在主连接事务中。
