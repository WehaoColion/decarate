# 安卓知识模块与 Obsidian 的能力差距及实施路线

交付状态：独立分支中的候选源码和对标路线，等待本地 Android 编译及真机验收；本轮未构建 APK。既有能力、此次候选和后续路线分别标记。

核对日期：2026-10-06。应用代码基线：`WehaoColion/decarate@2527d8bc7c6272d3c20cc9f7c017fa6ad7168d18`。比较对象是 Obsidian 的安卓可用工作流与官方核心能力，不把所有社区插件视为官方内置能力，也不把桌面鼠标操作直接当成手机操作。

提交基线：`main@348eddfe87fa372a194490c7fcf44870ca9bbcef`，已包含后来合并的 PR #11。上述审计基线保留以便复核，默认进入编辑的状态已更新为已合并。

## 1. 判断

现在的安卓知识模块已经不只是一个输入框。它有独立文档、分块编辑、原文与公式排版预览、图片和联系人等块、回收站、版本、资料库筛选、本地保护、知识问答和可触控画布。把这些写成“全部缺失”会导致重复建设。

真正的缺口是：内容虽然能存进去，但跨笔记的组织与找回能力不足；手机端对复杂结构化页面的写入能力落后于已有电脑端；开放文件与迁移能力还没有形成和 Obsidian 同等清晰的使用契约。首页增加更多卡片解决不了这些问题。

最值得先补的是可复用的文档关系索引，然后才是行内链接补全、精准定位、图谱和重命名维护。本 PR 实现第一组可操作能力，完整对标路线在后文。本文不会把尚未实现的路线写成已交付功能。

## 2. 审计证据与边界

检查了 Rust 持有的 Android 模板 `sourcegen/kotlin_sources.rs`，重点为 `NoteStudioSheet.kt`、`NoteDocumentEditor.kt`、文档模型和文本访问器；并检查 `android_knowledge_compat.rs`、`android_canvas_ui.rs`、`android_ai_workflow.rs`、`android_document_markdown.rs` 及最终生成器接入位置。

以下“缺口”是指这些真实安卓路径未形成对应完整工作流，不代表仓库中任何平台都没有同名字样。尤其不能把 Windows 代码当成 Android 已完成。`StructuredKnowledgeReader` 明确展示“在电脑端编辑”，且 `android_knowledge_compat::render` 会将复杂页面导入该保护性阅读路径。

源码可以证明入口、数据处理和保护边界存在，不能代替真机操作、流畅度和跨设备一致性测试。对系统分享接收、任意附件编辑和复杂格式导入，证据不充分的部分保留为待核验。

## 4. 本 PR 的实际产品路径

知识首页只增加一个紧凑的“关联与检索”入口。点击后进入有返回按钮的独立工作台，不把全部反链、标签和诊断直接堆在首页。

用户可以按标题、正文、资料库多词检索，再切换全部、标签、未见双链和待解析。文档卡可以直接沿原有路径打开，也可以先查看关联。单篇关系页展示本页链接、引用本页、未建双链的提及和标题大纲。点击目标可以继续查看关系，点击打开文档才进入原来的阅读/编辑路由。

“复制双链”是显式剪贴板操作，生成 `[[资料库/标题]]` 或唯一的 `[[标题]]`。重名或保留符号造成不确定时不生成错误链接。此版本不自动改正文，也不靠自动创建几十篇空文档营造知识图谱。

内容扫描只发生在工作台打开时，索引和查询在后台协程执行。查询切换或文档/工作区更新会取消旧工作；发布结果前校验来源快照，避免显示其他账户或较旧笔记的索引。相同内容但不同列表实例也会正确重新建立来源身份。

加密文档在读取标题、正文和属性之前就排除，包括带加密信封的临时解锁对象。结构化/富文本正文不强行摊平，超过单篇 512,000 字符或本次总量 8,000,000 字符的正文也不进行部分扫描；标题仍可导航，界面明确显示遗漏数。“未见双链”只描述本次范围，不推断绝对没有联系。

列表每次显示 40 项，保留总数与继续显示入口；同一链接有超过 12 个同名候选时提示数量及通过检索查找其余候选，避免一张卡把工作台撑成长页面。代码块、行内代码、转义、注释中的常见伪链接不进入关系索引。该扫描器是有明确边界的常用语法支持，不是宣称完整实现 CommonMark/Obsidian 解析器。

## 5. 全面对标后的推进顺序

### 第一组：能连接、能找到、不能出错

本 PR 的关系索引、出链/反链、标签、待解析和标题检索是这一组的基础。下一步补编辑器 `[[` 自动补全、选择文本建立链接、打开指定标题/块，以及返回原编辑位置。所有跳转先沿原保存机制提交当前草稿，不能为了关系跳转另建一条绕过保存的路。

重命名采用稳定文档 ID 与可读路径的双层映射。在确认后的多文档事务中更新引用，整批可撤销；发生重名、并行编辑、删除和同步冲突时必须有预览及回滚，不允许字符串全局替换。

### 第二组：写作不停顿

实现真正的实时预览，不能简单把输入框换成只读 WebView。光标所在段落展示可编辑语法，非焦点段落显示格式；保留 UTF-16 选区、中文组合串、撤销分组、软换行、代码围栏和公式完整性。键盘变化和块高度变化必须沿用已经修好的光标坐标转换。

建立用户模板库、每日文档和上下文命令面板。每日文档要有工作区+本地日期的稳定身份，多次点击不重复创建；已有内容绝不被模板覆盖。模板变量仅支持声明过的安全变量，不执行任意脚本。写作场景可进一步提供人物卡、场景卡、章节目标和引用来源，而不是要求用户先学几十条设置。

### 第三组：内容长期保得住，结构在手机上也能改

先建立 `.md`、附件和 `.canvas` 的导入导出兼容层，再决定是否开放文件夹双向映射。通过 1,000/10,000 篇语料的往返验证，比较文字、顺序、链接、文件名、附件哈希和格式，不把“能导入一篇”当成迁移成功。现有独有结构化数据必须保留伴随元数据，不能静默丢弃。

为手机补类型化属性编辑、数据库式视图和局部图谱。先支持状态、日期、标签、数字、关系字段的安全修改与过滤，复用已有 `knowledge` 模型，避免再造第二种不兼容 schema。自动关系图和现有手动画布分开：前者解释引用，后者表达构思，允许显式把关系视图转换成画布，但不能互相覆盖。

插件体系最后建立稳定版本、权限、沙箱、失败隔离及卸载清理。不能把直接加载任意第三方 JavaScript 当成“已经拥有 Obsidian 插件生态”。兼容具体插件要逐个说明支持的平台 API，不能仅凭语言相同宣称能运行。

## 6. “赶超”的验收标准

首先比较任务完成情况：写一篇带图带公式的文章、把两篇笔记相连、从某人物找回相关章节、恢复误删与冲突版本、导出资料再由另一编辑器打开。功能入口存在只是开始，完成过程中丢焦点、跳屏或丢内容都算不通过。

随后在同一台手机、同一批本地资料、相同字体和网络条件下记录首次打开、继续输入、搜索、切换模式与标签的耗时；至少报告中位数、较慢的 95% 分位、峰值内存和电量条件。没有这些测量，不以“用了 Rust”推导一定更快，也不虚报领先百分比。

可靠性验收必须覆盖旋转、后台恢复、进程重建、低存储、保存失败、并发同步、修改标题后回退、加密状态变化及超大文档。所有破坏性操作有明确对象、确认及恢复路径。

本次没有进行 Obsidian 与本应用的同机性能测试，没有完整 Android 编译和真机重新安装。因此本 PR 的状态是“关系导航候选实现及全面对标路线”，不是“已全面超过 Obsidian”。
