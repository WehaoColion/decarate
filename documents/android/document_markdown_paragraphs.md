# 文档 Markdown 预览段落边界验收

## 问题与范围

分块文档编辑器的 `documentMarkdownPreviewText` 原来使用单个换行连接文本块。CommonMark 会将连续普通文本行解析为同一段落，因此编辑页中独立的多段正文在预览里变成一个段落。这是预览投影错误，不应通过修改用户正文、重存文档或改变全局 Markdown 软换行规则来掩盖。

本次只改变文档预览的块间连接。普通文本块使用空行分隔；围栏代码、显示公式、表格以及明确的列表/引用等连续结构保留所需的单换行。单个文本块及其内部原文不做规范化，标题、块 ID、组合输入、保存、撤销、光标和 AI 回答渲染器均不改写。

Rust 模块 `native/gridtimer_native/src/sourcegen/android_document_markdown.rs` 在最终源码输出时只替换文档编辑器的一处连接表达式，并加入纯 Kotlin 辅助函数。模板锚点缺失或重复时生成失败，不静默漏掉修复。新 JVM 测试由生成器正常输出。

## PR 初始验证记录

独立 Kotlin/JVM 宿主测试 26/26 通过，测试使用本次 Rust 常量对应的生产投影代码和测试方法。宿主以 `kotlin.test` 替代 JUnit 断言，两个编辑器入口用例使用最小数据类型替身；这不是完整 Android/Compose 编译。覆盖独立段落、两个标题与五段正文、500 段、单块 CRLF 原样保留、内部软/硬换行、Unicode、空内容、实时草稿读取、预览资格，以及代码/公式/表格/列表/引用的代表性边界。

将单换行错误重新注入后，26 项中 22 项失败；移除围栏代码连续性判断后，4 项失败。两种变异均先实际编译成功，生产文件未替换为变异版本。

另将 Kotlin 实际输出交给独立 CommonMark 解析器（markdown-it-py）核对 8 组 HTML 结构：分段、标题、代码、表格、列表、引用、缩进代码、单块导入，全部通过。旧的单换行投影可复现三个段落变为一个 `<p>`。这不是应用原生 pulldown-cmark/KaTeX/WebView 的端到端验收。

生成器改动前的完整字节已与 Git blob `69eca5f95135a136ec6e9a12c38d382677ae3ce2` 一致核对。仅新增 9 行注册与调用，不移除现有转换。

以上为 PR 初始工作环境的验证记录，该环境未执行 Rust、Gradle、Android 正式版或真机检查。它不能替代本机的完整构建与应用原生渲染验收。

## 本机修复与验收

本机审查补充了七类边界规格，投影规格共33项：缩进代码内的公式符号、引用与嵌套引用中的代码围栏、列表代码围栏及其空行、容器结束后的围栏状态、多行列表续行、未闭合公式和引用内的空行。代码状态绑定引用深度和列表缩进；数学分隔符先检查配对，未闭合分隔符按普通原文处理。两次顺序扫描保留原文字节，不要求用户迁移或重存笔记。

完整验收通过现有工具入口执行：`pwsh -NoProfile -File tools/android.ps1 -Mode build -GradleHeapMiB 2560 -GradleWorkers 2`。构建冻结应用、生成器和验证工具的输入指纹；构建期间输入发生变化必须重新验收。变异验证直接使用 Rust 所有的生产辅助函数、实际预览函数和同一份33项规格；只修改注释应通过，移除段落分隔或代码围栏连续性判断必须由对应业务规格失败，编译错误不算捕获变异。

最终执行结果、实际投影交给应用原生 Markdown 渲染器的结构检查，以及正式签名候选 APK 的身份和哈希，记录于本机验收目录，并在本版更新说明中汇总。没有连接手机时，以下交互项仍为待验收，不能用电脑端编译和结构检查替代。

本机最终结果：893项Rust领域规格、130项生成器规格、66项打包器规格通过；Android正式版17套件264项通过，其中本模块33项全部通过，lint及assembleRelease通过。五组实际编译的变异中，原版、注释变化和恢复原版通过；段落分隔与代码围栏延续判断被移除后，指定业务规格均失败。12组实际投影经生产渲染器的原文与HTML结构检查通过。正式签名候选APK为2.23.2.12/22281，详见[本版构建与交付结果](../releases/android/release_notes_v2.23.2.12.md)。

先保留本地未提交内容、配置和已有候选修复，不得强制重置。按项目原有构建流程生成 Kotlin，运行 `DocumentMarkdownBlocksTest`、新增 Rust 模板测试、格式及既有门禁，完成正式版编译。检查实际生成的 `NoteDocumentEditor.kt` 调用 `documentMarkdownFromBlocks`，而不是只验证新 Rust 文件存在。

用非敏感测试文档建立两个标题和至少五个独立正文块。切换到预览后应保留五个独立段落，顺序和文字一致，再切回编辑时块数、块 ID 和正文不得改变。新旧已保存笔记、尚未保存的实时草稿都需检查。无须重新输入、补空行或执行数据迁移。

分别验证一个块内的完整 Markdown，以及由多次回车拆成多个文本块的内容：普通段落、软换行和显式硬换行、标题、引用、编号和待办、围栏代码及其中的空行、表格表头及数据行、`$$` / `\[...\]` 公式。确认公式实际排版可读，代码原文不多空行，表格不拆散。缩进/嵌套等复杂 Markdown 也应通过应用原生渲染器回归，不能用宿主策略测试替代。

回归连续换行光标避让、预览切换、撤销/重做、退出保存、加密笔记及 AI 回答渲染。对比切换前后序列化正文和块 ID，不应因预览产生编辑记录或改变内容。
