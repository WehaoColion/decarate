# Android「询问整篇文档」闪退修复

## 复现路径

知识模块 → 打开一篇文档 → 文档菜单/插入命令中的「询问整篇文档」。

## 代码侧风险点

当前入口会在文档编辑状态仍存在时创建知识 AI 对话框。AI 对话框把 `SnapshotStateList` 类型的 Agent 选择集合放入 `rememberSaveable`，同时在首次组合时同步构造知识来源。前者不应作为 Bundle 持久状态跨文档/对话框状态持有；后者若遇到旧版、结构化或异常文档投影，异常会直接发生在 Compose 组合阶段。

本次修复不依赖猜测某一种文档格式，而是同时收紧入口和组合边界：

1. Agent 资料选择列表改为普通 `remember`，不再把 `SnapshotStateList` 注册为可保存状态。
2. 从文档进入 AI 时默认进入「问知识库」模式，并把当前文档作为优先来源，而不是先进入无来源的直接问模式。
3. 打开前重新从当前 `AppData` 解析文档 id；已删除、已锁定或已失效文档不给 AI 入口继续执行。
4. 知识来源构造放入失败隔离边界。旧版/结构化异常资料无法投影时返回空来源，由现有 UI 提示，而不是让组合异常终止进程。
5. 对话框状态只携带文档 id，正文继续沿现有来源构造的有界节选进入请求，不把整篇正文放进 `rememberSaveable`。

## 不改变

- 不修改文档正文、版本、附件或保存逻辑。
- 不放宽加密文档访问。
- 不改变普通「直接问 AI」入口。
- 不改变 Agent v2 的授权、深度核验和最终确认保存边界。

## 本地验收

- 普通 Markdown 文档打开后点击「询问整篇文档」，应稳定打开 AI，并默认处于「问知识库」。
- 长文档、旧版文档、结构化页面重复执行该路径，不应闪退。
- 已删除/锁定/失效对象应给出不可读取提示，不打开 AI。
- 从知识首页直接打开 AI 仍默认「直接问 AI」。
- 打开/关闭整篇文档 AI 多次，旋转/后台前台切换后不出现 saveable state 异常。
- Agent v2 的资料勾选、深度核验、取消与保存门禁继续工作。
- 完整执行 Rust/sourcegen、Android JVM、lint、Release assemble，并在真机复现原路径。
