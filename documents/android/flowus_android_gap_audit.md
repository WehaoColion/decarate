# FlowUs 对标与安卓结构化阅读升级

核对日期：2026-10-06。代码基线：`a140364a1540d7437dd40b05a7d801921c6c1a2b`，包括合并后的 PR #12。本文比较的是实际安卓路径，不把 Windows 的实现当成手机已经能用；没有安装 FlowUs 安卓客户端做逐项同机测试，因此官方平台能力与特定手机操作不能混为一谈。

## 判断与范围

普通文档的分块编辑、图片、公式预览、版本、回收站、资料库、AI 问答、手动画布已存在；PR #12 已加入关联检索、出链/反链、标签及常见双链解析，不能重新记为缺失。

明显缺口集中在两个层次：结构化页面在手机上仍是保护性只读视图，某些已存储的块结构根本没有变成可用交互；更大的多维表、模板、同步块和团队协作也没有形成安卓完整工作流。前者直接影响现有资料的阅读，本次先修这一组；后者列为实际待实施项，不以几个按钮宣称全量完成。

本次只增强 `hasStructuredKnowledge()` 路由里的结构化页面。普通可编辑笔记仍走原编辑器，不会被强制改为阅读页。也没有解除防止结构化数据被扁平编辑器覆盖的保护。

## 已检查的实际代码

`sourcegen/kotlin_sources.rs` 中的 `NoteStudioSheet.kt`、`NoteDocumentEditor.kt` 与数据模型；`android_knowledge_compat.rs` 的 `StructuredKnowledgeReader`；`android_knowledge_navigation.rs`；`android_canvas_ui.rs`；知识共享模型及源码生成器注册。关键事实是原阅读器把 `table_of_contents` 和 `columns` 分支写成 `Unit`，有序列表显示点号，todo 只读，toggle 没有折叠行为。原父层级查找逐块重复查询，正文整页用 Column 一次组合。

## 本次落地的用户行为

打开一个已有结构化页面，顶部固定“返回、目录、查找正文、待办定位”。点击目录或搜索结果会展开目标所有折叠祖先，再滚动到准确的正文块并描边提示。定位指块而不是词的字符位置。三级目录仅认 heading1/2/3 元数据，不把代码里的井号或原文中的井号误当标题。

收起外层不清除内层折叠状态；只展开目标的祖先，不把全页全部展开。折叠状态仅属于本次阅读，不写回 saved collapsed，不更改云同步内容。异常 parentId、重名 ID、循环或超过64层的链被显式提示并按根层显示，宁可保留原文可见，也不隐藏损坏结构。列表键使用原位置，避免重复ID造成键冲突。

查找范围明确限于此阅读器渲染的正文块、图片说明和表格单元格。富文本独立区、页面属性和批注仍展示，但不冒充已可精准检索。搜索匹配按块计数，所有结果通过列表浏览，不默默截去后面的条目。未完成待办入口只定位，完成状态仍由原数据决定，不会出现点了看似打勾但没保存的假操作。

代码复制只有用户点击后才进入剪贴板。页面解锁保护、原图片回调、标签、属性、数据库字段、正文与批注保留。没有新增网络请求、AI调用、账号连接、永久索引、数据格式迁移或文档写入。
