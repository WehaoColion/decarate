# Android 知识 Agent 深度核验升级

## 目标

在不扩大数据授权范围、不自动修改来源、不自动保存结果的前提下，把现有“检索 → 阅读 → 生成草稿”升级为可见计划、可选第二阶段复核和本机保存门禁。

## 新流程

1. 用户选择 1–30 条未删除、未加密的便签或知识页，并查看完整发送预览。
2. App 根据任务目标生成可见执行计划；比较类、待办类、复盘类任务会增加对应步骤提示。
3. 首轮仍使用现有本机工具循环，只在本次授权范围内搜索、分段读取并生成一份内存草稿。
4. “深度核验”默认开启。首轮成功后，第二阶段不读取首轮草稿正文，而是围绕同一个原始目标，在完全相同的授权资料范围内独立重新检索、阅读并生成替代草稿，降低首轮遗漏、来源冲突和来源内提示注入继续传播的风险。
5. 两阶段完成后，本机执行结构化核验：草稿完整性、检索/读取/草稿工具链、来源编号仍属于授权范围、来源去重、待办去重，以及深度核验是否真正完成。
6. 只有本机核验通过时，保存按钮才允许提交。保存仍沿用原知识页持久化路径，并需要用户最终确认。

## 用户界面

- 任务 Agent 增加“深度核验”开关。
- 运行前展示执行计划和可能增加的模型调用。
- 结果页显示实际计划、本机核验项目，以及带“首轮 / 复核”阶段前缀的工具记录。
- 用户仍可以编辑标题和正文；界面会明确提示，核验记录只覆盖模型生成版本，最终保存内容以用户当前编辑内容为准。
- 若用户要求深度核验但第二阶段失败，首轮草稿可以显示供检查，但保存门禁保持关闭；可重试，或关闭深度核验后重新运行。

## 不变的边界

- 不读取未选择资料。
- 不读取加密资料。
- 不修改、删除或覆盖来源。
- 不自动创建待办或写回属性。
- 不把首轮草稿正文当作第二阶段指令输入。
- 两阶段都沿用现有 `store:false` 请求设置；自定义 AI 服务的留存规则仍由服务商决定。
- 取消任务后，现有 taskId/AtomicBool 取消边界继续阻止后续模型请求。

## 建议本机验收

- 深度核验开启：确认首轮与复核工具记录均出现，复核成功后保存按钮可用。
- 深度核验关闭：只运行首轮，仍显示本机来源/工具链核验并允许保存。
- 第二阶段主动断网或取消：首轮草稿可以显示，但核验失败且保存按钮不可用。
- 修改任务目标、资料范围、模型配置或工作区：旧草稿失效，不能继续保存。
- 模型返回越权来源、重复来源或重复待办：本机核验拒绝保存。
- 用户编辑草稿后：显示“核验仅覆盖模型生成版本”的提示，最终保存当前编辑内容。
- 覆盖安装后确认原笔记、知识页、便签、搜索、双链、结构页及已有问答功能不受影响。

## 当前未包含

本次没有增加自动改写原文、创建真实待办、属性写回、跨模块财务/计时工具、任务跨进程恢复和第三方 Provider 的 Chat Completions 工具调用适配。这些仍适合后续单独迭代。
