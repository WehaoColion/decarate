## 知识页保存队列

调整普通知识页和便签的自动保存排队方式。连续编辑同一工作区中的同一篇文档时，若相邻的旧自动保存请求尚未开始写入，可以用最新完整草稿替代，减少把每一份中间稿都依次落盘形成的积压。已经开始执行的保存继续完成，不能在写到一半时换成另一份内容。

替代只发生在相邻自动保存之间。点击明确保存、创建本地版本、删除、加密状态变化和退出时的保存，继续按接受顺序执行；这些操作构成保存屏障，后面的自动保存不能跨过。不同文档、不同工作区的请求也不能相互替代。队列已经关闭、正在退出或无法接受请求时，返回失败状态，不把未执行的请求显示为保存成功。

加密文档继续使用先密封内容再提交保存的保护流程，不把未密封的加密文档明文放入可替代的自动保存项。保存优化保留原有的账户隔离、工作区隔离和加密锁定约束。

## 退出编辑与草稿恢复

普通文档退出编辑时，先捕获本次完整草稿、原文档、工作区和编辑会话，再把恢复草稿写入及正式资料提交作为同一个顺序保存请求交给后台执行。耗时的恢复文件写入不再直接放在界面线程上执行，降低点击创建本地版本或退出编辑后界面长时间被保存操作占用的机会。

已经接受的退出保存请求，不因编辑组件退出而仅依赖该组件的协程继续执行。恢复草稿写入、正式提交以及最终结果仍按顺序核对；恢复草稿或正式资料未保存成功时，继续保留失败状态和可恢复内容，不提前关闭编辑页，也不显示保存成功。界面上的旧保存回调绑定原文档、原工作区和原编辑会话，切换账户、工作区或打开另一篇文档后，旧回调不能关闭新页面或替换新页面的保存状态。

加密文档保留原有密封与恢复保护路径。本次没有将该路径替换为可能晚于后台锁定才处理明文的自动保存方式。

## 偶发慢保存的定位

新增保存阶段耗时记录。某个阶段超过一秒时，记录队列等待、实际保存执行、写锁等待、快照编码、保存前核验、数据库提交以及恢复副本写入等阶段的名称和耗时，便于在问题再次出现后区分时间究竟花在排队、计算还是本地文件写入上。

诊断记录只包含固定阶段名称与时长，不记录文档正文、文档编号、账户、工作区名称或凭据。阶段记录本身不能证明每次保存都会很快，也不能代替当次设备日志。

本次用户反馈的近一分钟等待只发生过一次，目前没有取得那次等待的手机诊断日志，未在用户设备上复现同一故障。本次修改针对已经确认存在的自动保存积压和界面线程文件写入路径，尚不能将那次偶发等待归因于某一个已经实测的单一原因，也不能声称偶发故障已经通过真机复现和消除。

## 金额输入与两位小数

收入、支出、资产和负债的逐笔金额改为支持小数点后最多两位，输入框使用带小数点的数字键盘。输入文字和已保存的金额分别保存状态，输入 `58.`、`58.1`、`58.12` 时保留正常的中间编辑过程，避免每按一个字符就把小数点转换掉或拒绝。

保存 `58.90` 后，重新查看或编辑时保持该金额；保存 `0.01` 后，不能因为它的整元部分是零就被当作空记录过滤掉。展示统一保留两位小数，整数金额显示为 `58.00`。合法输入上限为每笔 `999,999,999.99` 元。

金额的精确值采用整数分表示，不通过浮点金额累加。两笔 `0.01` 的合计为 `0.02`，收入减支出、资产减负债及相应报表读模型采用同一精度。超过两位小数、不合法字符、空输入或单独的小数点不能提交；这些未完成的输入保留在编辑草稿中，不把旧金额改成零，不静默截断多余小数。需要录入零值时，可以明确填写 `0` 或 `0.00`。

## 旧账、备份与同步兼容

旧账的整数金额继续按原来的人民币元解释。例如，原始记录里的 `58` 仍为 `58.00` 元，不被误读成 `0.58` 元。新增精度字段保存整数分，同时保留原来的整元字段；原有月度参数增加对应的精度保存与读取通道，原来的字段名称和旧记录内容继续保留。

用于计算的分视图只在本次计算过程中生成，不作为原始财务资料保存、导入或同步。备份读取在强类型解码之前检查该计算标记，防止回退解码忽略标记后把分当成元，再放大一百倍。整元字段与精度字段不一致、精度不是整数或包含未支持的精度字段时，拒绝相应保存或导入，不用整元值静默覆盖精确金额。旧数据的缺失标记和没有新增精度字段的历史整数记录继续保留。

本轮配套 Windows 1.1.0.5 已正式发布，安卓使用独立版本 2.23.2.1。Windows 客户端接入相同的精度字段、金额读取与计算，配套同步服务增加精度保护，已完成正式文件及实际运行身份核验。尚未升级的 Windows 旧端不能安全读取或编辑含新精度字段的工作区；应使用本版 Windows 与本版安卓配套，不能将旧端的整元显示当成完整的小数金额。

新增的共享精度字段及保存、恢复和合并校验共同保留整数分。同一条未修改的旧端记录遗漏新字段时，合并仍保留已有小数；旧端发出无法证明原有小数仍完整的更新时，新的同步边界拒绝采用该更新，避免把分金额静默改成整元。新版客户端明确输入 `58.00` 时会保留 `5800` 分这一修改意图，允许将原来的 `58.99` 正常修改为 `58.00`，不能为了省略整元精度字段而恢复成旧金额。实际跨端编辑与保护能力以各设备及服务正在运行的版本为准。
