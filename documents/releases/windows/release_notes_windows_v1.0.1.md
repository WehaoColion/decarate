# Windows 1.0.1

发布状态：已发布并完成正式运行验收。当前 Windows 版本为 1.0.1，实际安装文件记录在 `release_artifacts/current/release_manifest.json`。

## 独立版本

Windows 从 1.0.1 开始单独编号，后续修订使用 1.0.2、1.0.3。客户端标题、同步服务、后台守护程序及 Windows 发布文件保持一致。安卓沿用自己的版本序列，两端发布互不递增对方的版本。

此次重编号保持同步协议、数据目录、账户和配对身份不变。既有桌面入口与登录自启动任务继续使用固定入口解析当前 Windows 版本。

## 修复与优化

启动器和发布程序兼容安卓发布记录中的源码指纹。旧安卓记录可以继续使用，新记录中的指纹仍须符合格式校验，错误记录不会被放行。

同步服务在当前进程内复用已经成功校验且内容未变的恢复文件结果，减少启动和备份时重复解析历史内容。每次复用仍重新核对完整文件哈希；缓存有数量上限，不保存账户正文，不依赖磁盘上的完成标记。

发布过程先固定源码并完成回归、程序完整性检查和隔离启动验收，再原子更新 Windows 文件。安卓正式 APK 保持原来的内容及修改时间。

## 验证记录

本轮自动回归去重后 1,122 项通过、0 项失败，9 项为另行执行的性能或原生交互检查，未计入通过项。客户端隔离自检、真实数据副本启动、正式服务接管、公网 HTTPS 与签名地址发现、自启动任务重复触发均已通过。

发布前后，桌面数据、服务端各表、凭据、配对身份及安卓 APK 的字节和修改时间均保持一致。重复触发自启动任务后仍是同一个服务进程，验收时未打开客户端窗口。

正式环境这次初始化耗时 303,771 ms，约 5 分 4 秒；包含 218 份运行时恢复文件的隔离副本首次就绪耗时约 14 分 35 秒。大量历史文件下的冷启动仍需优化，这两个结果不构成固定启动时间承诺。

完整证据位于 `release_artifacts/verification/v1.0.1-windows-release/`。本版没有合入仍存在失败案例的附件隐私清理候选修复。全面审计继续保留这一问题，以及真实重启、锁屏和长时间运行的验收边界。
