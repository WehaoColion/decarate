# Windows 1.1.0.5 更新说明

说明更新时间：2026-10-02 22:58（北京时间）。正式版本：1.1.0.5。

**已正式发布。** 客户端、同步服务和同步监督程序统一为 1.1.0.5。正式文件完整性复验通过，经桌面原有 TenRate 入口打开的实际客户端窗口显示“十倍率 Windows v1.1.0.5”。主同步服务及其父监督程序的实际路径、版本、源快照与文件哈希均与正式清单一致。

## 金额读取、计算和显示

本版配合 Android 2.23.2.1 的金额精度修复。财务逐笔收入、支出、资产和负债支持精确到人民币分，报表、净现金流、净资产与财务风控读模型使用同一单位计算。金额显示固定保留小数点后两位，原来的 `58` 元显示为 `58.00` 元，`58.90` 元不会被显示或保存成 `58` 元。

旧的原始金额字段保持人民币元语义，新增的精度字段保存整数分。计算时生成临时的分视图，原始账目保持原字段与精确值共同保存，避免把整份历史账本直接改成分后让配对设备误读一百倍。原有月度金额参数增加对应的精度读取与保存；整数旧记录没有新增字段时继续按原值解释。

收入、支出、资产负债、季度和年度汇总以及风控相关的金额读模型使用精确分值。仅有 `0.01` 元的记录也属于有效记录，不能因为整元部分为零被丢弃。金额平均值按分处理后展示两位小数，符号和金额分别保留，负现金流及净资产变化可以显示到分。

## 编辑与保存保护

金额编辑过程保留独立的文本状态。`58.`、`58.1`、`58.12` 可以正常连续输入；空输入、单独的小数点、超过两位小数或非法字符不能提交，也不把原金额覆盖成零。取消编辑保留原始记录。整元与新增精度不一致时，不能通过忽略精度字段继续保存。

明确将 `58.99` 修改为 `58.00` 时，保留 `5800` 分这一编辑意图。它与旧端传输时遗漏精度字段属于不同情况，不能为了省略整元精度字段而恢复成旧金额。

财务资料无法按其精度安全读取时，界面保留待核对状态，不继续给出看似完整的合计。临时分视图带有计算标记，存储与备份入口拒绝将它作为原始财务资料写回；备份导入在原始 JSON 层面检查该标记，避免忽略标记后重复转换金额。

## 配套服务与跨端同步

客户端、同步服务和同步监督程序使用相同的 Windows 1.1.0.5；Android 使用独立版本 2.23.2.1。账户、登录、原资料位置和配对关系继续沿用。尚未升级的旧 Windows 不能安全读取或编辑带新精度字段的工作区，因此应使用本版与新版安卓配套。

同步合并增加金额精度保护。同一条记录没有修改时，旧端遗漏新精度字段的传输可以保留服务端已有的准确分值；旧端对带小数账目提交无法证明精度仍完整的更新时，拒绝该更新。即使改动前后恰好都落在同一个整元范围内，也不能据此认定可以丢掉原来的小数。

删除记录继续保留可核对的历史精度；支持精度的新客户端可以提交新的整元与分值一致的修改。备份恢复、资料清理和原有强类型保存路径同时保留精度字段，避免只修输入框而在重新打开、恢复备份或同步后再次丢失小数。实际保存及同步业务测试也覆盖了旧记录缺少编号时的身份补全与精度保留。

## 财务核对与版本记录

本版财务计算和核对使用分值。受金额单位变化影响的已有核对将失效，需要重新核对对应的收支、现金、资产或负债。资料未变化且仍与当前指纹匹配的确认继续保留；失配期间相关风控判断显示待核对。原账目与保护配置保留。

本次仅记录 1.1.0.5 的金额兼容与保护内容，已有版本说明继续保留。更新记录仍支持复制，说明时间按北京时间显示到分钟。既有性能优化、图标和固定桌面入口继续使用。

## 桌面入口与真实运行

桌面继续保留一个本产品快捷方式 `TenRate.lnk`，指向无版本的 `TenRate_Desktop_Launcher.exe`。它按正式清单解析并打开最新客户端。本轮检查实测解析到 1.1.0.5，实际客户端 PID 为 55844，窗口标题为“十倍率 Windows v1.1.0.5”。本次桌面维护没有需要再次删除的旧产品图标。

直接检查了正式主同步服务：8917 的实际监听 PID 为 55580，健康响应版本为 1.1.0.5，父监督程序 PID 为 41812。客户端、服务和监督程序的完整映像路径、大小及 SHA-256 均匹配正式清单；观测期间三个进程及主监听保持一致。PID 是此次验收时的记录，不作为以后每次启动的固定标识。

旧客户端先通过现有版本交接协议完成保存屏障并正常退出，没有强制结束产品进程。第三次发布的原生进程已完成正式清单提交与桌面维护，但外层 PowerShell 包装未自行返回；仅清理了确认没有活动子进程的任务包装进程。因此不将该外层包装描述为退出码 0。随后独立调用正式发布验证器已实际取得退出码 0，并完成上述主服务与客户端运行核验。

验收记录位于 `release_artifacts/verification/windows_v1.1.0.5/`：`package.log`、`package_attempt_3_acceptance.json`、`post_publish_verify.log`、`safe_old_client_exit.json` 及 `client_runtime_identity.json`。前两次失败尝试另留日志，第二次失败的完成记录不作为第三次正式发布证据。
