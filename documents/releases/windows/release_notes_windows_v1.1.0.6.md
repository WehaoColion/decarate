**Windows 1.1.0.6 已正式发布。** 用户已明确回复“授权正式发布 Windows 1.1.0.6”。正式清单已提交到本版，发布日志明确记录发布完成，独立发布验证器退出码为0；固定桌面入口已打开本版实际窗口。Android 保持2.23.2.1。本说明保留此前审批拒绝、首轮发布停止及实际界面验证的限制，不把历史候选记录改写成当时已经发布。

## 修复的问题

在财务编辑过程中，输入框保留金额文本，底层金额则保留最近一次合法值。本轮已经在正式1.1.0.5的实际窗口复现：将58.90元继续输入为58.901元，输入框提示“请输入金额，最多两位小数”，但保存入口仍可操作，“当天收支已记完整”也能被确认。最终磁盘中的支出仍为58元及5890分，并且已经写入当天确认时间。也就是说，输入错误虽然有提示，旧金额仍被当作本次确认的依据。

本次已在源码中补齐当前金额草稿的提交检查。存在无效输入时，保存和财务核对受到阻止；错误内容保留在输入框中，原来已经保存的记录保留，使用者可以继续修正或取消。全局保存、切换期间的隐式保存及退出保存也必须遵守同一判断，不能只禁用一个可见按钮后仍让其他入口提交旧金额。

金额的正常连续输入继续支持 `58.`、`58.1` 和 `58.12`；有效金额按整数分保存与计算，`0.01` 元记录保留。输入修正后，才能按照当前金额继续保存和核对。直接把58.99元改成58.00元，应准确保存为5800分，不能恢复成旧小数，也不能把未完成输入默认为零。本次不改变上一版已发布的精度字段与同步协议。

金额草稿按记录和工作区区分。跳转日期或月份之后，未完成的错误输入仍不能绕过核对；仅更换同步地址不会丢掉当前工作区的错误草稿。记录已经删除、被替换或实际切换工作区时，按对应记录处理草稿，避免无关旧输入长期阻挡后续操作。

财务输入错误也不能妨碍无关文档保存。知识页面和便签的正文自动保存、打开阅读与富文本编辑器、导出已保存文档、恢复文档或便签、保存转写内容，均使用相应文档的保存范围。它们可以保留文档修改，同时不会顺带提交尚未完成的财务金额。

## 候选版本实际交互复测

在原隔离资料上启动经过哈希核对的1.1.0.6候选客户端，共留存21条窗口状态记录。这是观察记录数量，不是21项独立测试全部通过。测试继续使用物理桌面、真实键盘和可用的控件树，未登录真实账户。

重新输入58.901元后，界面保留错误内容并提示修正。按Ctrl+S之后仍显示未保存，磁盘中的金额、记录更新时间和原确认时间均与操作前相同，没有把旧金额冒充成本次有效提交。核对控件在键盘Tab导航中被跳过；切换到前一天后，未完成提示仍保留，“定位输入”可以返回原日期并将焦点放回58.901金额框。

保留无效财务草稿时，进入知识页并把标题改成“本机交互验证_20261003_v6”，页面显示本地已保存。磁盘核对确认新标题、完整中文正文和对应本地版本已保存，而财务金额及原确认时间没有被顺带改写。返回财务页后，无效的58.901草稿仍保留。

在知识页按Alt+F4，程序明确提示金额未完成，窗口保持打开，并提供继续编辑入口。选择继续编辑后可以回到财务页处理原草稿。使用“恢复原金额”后金额回到58.90元，磁盘仍为5890分，当天确认状态为未确认；再次清空金额时，空输入继续被识别为未完成，没有自动当成零。

随后将金额修正为58.00元并按Ctrl+S，界面显示已保存，磁盘中的精确金额为5800分。以Alt+F4正常退出后重新启动同一隔离资料，风控页显示58.00元，知识页保留修改后的标题和完整正文，计时格子仍为暂停状态及28秒。第二次复核完成后再次以Alt+F4正常退出。两次候选运行均有新的“EXIT clean”记录，对应进程已经退出，测试资料继续保留。

阅读入口已触发本地页面加载，运行日志记录了“RICH_EDITOR_PAGE event=finished”；由于没有取得阅读内容的可视验证，这一项只记录为加载事件完成，不记为阅读界面验收通过。富文本快捷键尝试没有打开编辑器，当前合成笔记仍是内容块编辑模式，因此富文本编辑器的实际窗口验收未完成。后文的阅读、富文本、导出和恢复测试结论属于自动化业务回归，不能代替这些实际界面验证。
